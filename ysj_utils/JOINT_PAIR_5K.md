# Joint Delta / Joint+EE 连续实验

本轮每组训练 5000 次参数更新，global batch size 128，bf16，随机种子 42，action chunk 50，RTC 关闭。相同预训练权重、训练清单、当前 joint+EE 状态输入；Joint+EE 增加权重 0.1 的 EE delta 辅助监督，执行仍使用 joint。它检验的是增加 EE 监督的作用，不是 EE 控制器优劣；没有训练绝对 joint 组，也不能单凭这两组评价所有动作参数化。

`5k step` 是 5000 次 optimizer 更新，不是 5000 个 episode。按 BS128 约处理 640000 次样本抽取。训练循环已修复数据迭代结束时计数虚增的问题。

在团队 Linux 模型环境运行 `python ysj_utils/run_joint_pair.py --help`。必须提供独立输出路径以及经过核实的数据、原始 HDF5、配置路径和 GPU 编号；脚本不接收或保存 SSH 密码。

执行顺序：审计原始关节/EE 标签与 LeRobot 帧对齐；生成匹配配置；分别计算动作归一化统计；两组各跑 5 步训练并完成 checkpoint 加载和一条仿真；全部通过后顺序训练两组 5000 步；最后两组各评测 7 task × clean/random × 25 episode = 350 次，共 700 次正式评测。

出现非有限 loss/梯度、子进程报错或评测结果缺失时停止后续阶段。只管理脚本自己启动的进程；不终止其他人的任务。日志、GPU 快照、阶段状态写入 `--run-dir`；完整评测成功后写入 `comparison.json`、`RESULTS.md`。`--dry-run` 可查看全部命令。`--resume` 只跳过同一计划下已完成阶段，不覆盖未完成训练。

本机检查覆盖参数转换、归一化、监督梯度、预算匹配、队列失败处理与评测结果校验。它不证明 H20 训练或 RoboTwin 已成功，更不保证成功率提升。真实效果以远端完整评测为准；单训练种子结果先作为初步证据。

用户明确要求直接跑正式预算时，可加 `--skip-smoke`。若已经完成同一 bundle 的配置和统计，可再加 `--prepared-bundle`，并指定新的 `--run-dir`，只执行两组正式训练和两组完整评测。复用前会校验预算、配置哈希及归一化收据，不覆盖已有正式训练输出。`--gpu-wait-seconds 21600` 可等待指定 GPU 最多 6 小时；不会终止其他任务。
