## 为什么先做这个实验

绝对目标要求模型预测目标关节角；chunk-relative delta则预测目标与当前关节状态之间的差值。后者可能改变目标分布及学习难度，值得在固定训练预算下检验，但也可能受观测误差和已有预训练表示影响。

直接依据是 [Demystifying Action Space Design for Robotic Manipulation Policies](https://arxiv.org/html/2602.23408v1)，其区分 joint/EE 空间、absolute/delta 参考方式，以及chunk/step级增量。我们借鉴实验维度和chunk-relative定义，不把论文提升幅度当成本项目预期收益。

本轮假设：在相同数据、模型起点和优化预算下，Joint Delta是否改善成功率或学习效率。可支持该假设的证据应是任务成功率与物理动作误差，而不只是归一化训练loss变小。

## 正式训练和评测标准

| 设置 | 值 |
|---|---|
| 全局batch size | 128 |
| optimizer steps | 10000 |
| 训练精度 | bf16；`enable_fp32=False`、`enable_mixed_precision=True` |
| 默认并行配置 | 8卡，每卡micro batch16，梯度累积1 |
| 训练任务 | 暂沿用新仓库50个clean任务清单；最终范围仍需团队确认 |
| 评测任务 | blocks_ranking_rgb、hanging_mug、open_laptop、pick_diverse_bottles、rotate_qrcode、stack_blocks_three、place_shoe |
| 环境与次数 | clean/random各25条/任务，共350条/checkpoint |
| 评测精度与执行长度 | 两组均沿用现有FP32推理、执行chunk长度50 |

两组共700条正式评测。旧的5000步FP32 checkpoint可用于验证评测环境，不作本轮匹配对照。5步、BS1的短训只用于排错，单独输出目录，不混入正式结果。

## 最小测试覆盖范围

2026-10-16 实际运行结果：**44项全部通过，0失败、0跳过**，使用 `--require-torch`。环境：Windows、Python 3.13.2、PyTorch 2.8.0 CPU、NumPy 2.2.3、SciPy 1.15.3、PyYAML 6.0.2。此前因缺PyTorch跳过的三项已经补跑。静态语法与Git diff空白检查通过。

- Joint：固定参考状态、左右臂与夹爪顺序、零运动、往返、输入不被意外修改。
- EE数学参考：局部坐标、已知旋转、四元数顺序和q/-q等价；不代表EE训练已实现。
- 源代码：配置解析、真实apply/unapply与Normalizer执行顺序、归一化horizon检查。
- PyTorch动作路径：实际字段拆分、55维padding、有效维mask、训练目标经过推理侧逆变换还原；图像/语言处理用替身，模型前向不在覆盖范围内。
- 实验接口：成对配置只改变动作表示与对应统计，拒绝错配统计/配置，350条结果完整性与对照条件校验。

补跑过程中发现测试原先要求反归一化结果必须float32，与上游实际行为不符：NumPy统计会使中间结果提升至float64。现保留严格数值误差检查，并执行真实推理服务的 `_unapply_batched_actions`，确认最终发送的动作确实为float32且数值正确；没有因此改动生产归一化算法。

最终可复查的测试计数、依赖版本与源码哈希见 `reports/action_minimal_2026-10-16.json`。测试报告的head是测试时的基础提交；source_sha256记录该次实际工作区代码，不代表基础提交原样通过了所有新测试。
