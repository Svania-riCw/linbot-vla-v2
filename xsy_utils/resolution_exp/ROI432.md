# ROI-432：固定视觉预算下的末端附近细节

本次交付是代码与验证工具，尚未启动 ROI 正式训练，也没有 ROI 成功率结果。
已有 384 全图实验及其 checkpoint、结果、共享 claim 均不由这些工具修改。

## 要证明什么

假设：在 **432 个视觉 patch tokens** 不变时，把一部分 wrist 全图预算分配给 head 相机中的左右末端附近，能够改善需要局部定位的操作，尤其是 random 场景。

这不是增加图像数量或扩大模型。保持三个输入槽位、模型结构、动作头和 teacher loss：

| 槽位 | 原 384 全图 | ROI-432 / 固定裁剪对照 |
|---|---|---|
| head | 384×384 全图 | 相同的 384×384 全图 |
| left wrist | 384×384 全图 | 左半 wrist 全景缩略图，右半 head 中左末端 ROI |
| right wrist | 384×384 全图 | 左半 wrist 全景缩略图，右半 head 中右末端 ROI |

两张画布各为 384 高 × 384 宽，每半幅为 384 高 × 192 宽。
Qwen patch16、merge2 得到每槽 12×12=144 tokens；总计 **432 patch tokens + 6 图像边界 tokens**。
画布接缝位于合并 patch 边界。ViT 仍跨整幅画布交互，不能把两个半幅理解成独立编码器。

默认 ROI 高度为原始 head 图高度的 1/2，宽度为该 ROI 高度的 1/2；固定裁剪中心为归一化坐标 `(0.35,0.5)`、`(0.65,0.5)`。这是预先设置的起点，尚未根据测试集挑选。修改尺寸/中心必须同时修改固定对照。
越界窗口保持中心和尺寸、补黑；末端在相机后方或投影中心不在画面内时，回退到对应固定中心并记录 fallback。
缺少标定、profile 不一致、坏帧或状态错位会报错，不随机替换训练样本。

保留 wrist 全视野采用 letterbox，存在实际代价：4:3 wrist 图放入 384×192 半幅后内容为 144×192，其余约 62.5% 是黑边。
所以名义各 72 tokens 不代表有效视觉信息量各半。需要看真实画布再判断压缩 wrist 是否过度；当前版本固定这个布局，避免同时改变多项设计。

## 一个重要的状态语义

本仓库 `Robot.get_*_arm_jointState()` 调用的是 `joint.get_drive_target()`。
因此现有 LeRobot `observation.state` / RoboTwin `joint_action/vector` 是**当前关节驱动目标**，不是实测 qpos。
当前方案明确使用两端同源的 drive target 做 FK，不把它称为精确观测到的末端位置。

`q_t → 双臂 FK → world → OpenCV 相机 → 原图 crop → Lanczos4 → 画布`

- 只读取未经归一化的当前 14 维状态；索引 0:6 / 7:13 为左右臂，忽略夹爪标量。
- FK 从实际 URDF 加载后的 SAPIEN joint frames 导出，包含 RoboTwin 的末端偏置；不猜机器人 link 长度。
- 相机使用逐帧 `intrinsic_cv`、world→camera `extrinsic_cv` 和对应 RGB 尺寸；不使用历史 320×240 常数。
- 当前 RGB 必须在缩到 384 前取 crop；按真实校准尺寸缩放投影坐标。
- 训练和推理都调用 `ROICanvas.prepare_sample()`。未来状态、动作、物体位置及 raw endpose 不参与选择 crop。
- 原始 endpose 仅用于**离线诊断** drive-target FK 与实际末端的米制误差、投影像素误差和默认 crop 覆盖率，不作为训练输入。
- 当前 head 及未来 head teacher 目标保持原样；未来各相机仍使用全图。

## 实验对照和判断

| 配置 | 作用 |
|---|---|
| `full432_matched.yaml` | 同样初始权重和训练设置的全图参照配方；生成配置不等于重训 baseline |
| `roi432_fixed.yaml` | 同样画布、裁剪大小和预算，固定位置 crop |
| `roi432_ee.yaml` | 只把 crop 中心改为当前状态 FK 投影 |

固定 global128 = micro4 × 8 GPU × accum4、workers8/prefetch4/pin_memory、seed42、FP32 开关、LR/优化器、10k scheduler、clean 50×50 数据和同一 clean norm。
从与 384 全图相同的原始 6B 权重开始；不能把已训练 5k/10k 的全图模型当作 ROI 的同预算起点。
配置生成器保留完整 source recipe，只新增输入表示字段以及独立输出/运行名、初始不自动 resume、5k 暂停设置。

5k 和 10k 分别评测相同的七任务 × clean/random × 25 回合，保留 14 项完整结果、视频及日志。
报告 clean/random/总体成功次数和成功率、逐任务差值、ROI fallback/覆盖率、稳定训练与推理耗时。

- EE 高于全图且高于固定 crop：支持“状态引导的内容分配”。
- 两种 crop 都高于全图、相互接近：更支持局部放大/布局，而非末端引导。
- 仅 clean 提升：不能称 random 泛化有效。
- 两种 crop 都下降：先检查投影偏差、wrist 分辨率损失和拼接布局，再设计下一次改动。

当前没有 ROI 数字，不能判断它已有效。历史全图结果只是参照，且初期 worker 轨迹等差异须保留说明。

## 在服务器准备真实几何（不启动训练）

以下从仓库根目录执行。用现有环境；不要修改共享 Conda 环境。
导出 profile 需要已有 RoboTwin/SAPIEN 和本实验实际 embodiment 资产。数据准备需要 numpy、OpenCV、h5py、pyarrow；预览另需 CPU torch/transformers/Pillow。

```bash
# 1. 在 RoboTwin 环境导出实际机器人 profile，并检查 8 组 qpos 的 FK。
# ROBOT_DIR 必须是当前 aloha-agilex 实际使用的 embodiment 目录，含 config.yml/URDF。
python tools/export_robotwin_roi_profile.py \
  --robot-dir "$ROBOT_DIR" --output /root/ql/roi432_inputs/robot_profile.json

# 2. 按正式 recipe 的 train_path 列表准备全部 50×50 当前帧 sidecar。
# 输出必须是新目录；错误时 manifest.complete=false，训练不能加载。
python tools/prepare_roi_geometry.py \
  --profile /root/ql/roi432_inputs/robot_profile.json \
  --dataset-list "$CLEAN_TRAIN_LIST" \
  --raw-root /2025233210/lmx/RoboTwin/data \
  --output /2025233210/ql/roi432_inputs/geometry

# 3. BASE384_YAML 使用已核实的正式 384 recipe，不能用旧的 50k 模板。
# 必须显式具备 workers8/prefetch4/pin_memory、micro4/global128/10k、
# pinned clean norm，且 model_path 是原始初始化权重。
python tools/prepare_roi432.py \
  --base "$BASE384_YAML" \
  --profile /root/ql/roi432_inputs/robot_profile.json \
  --geometry /2025233210/ql/roi432_inputs/geometry \
  --destination /root/ql/roi432_inputs/configs \
  --run-root /2025233210/ql/roi432_outputs

# 4. 用真实 LeRobot PNG 帧输出全图/ROI 对照、投影框和真实 processor token 报告。
python tools/check_roi432.py \
  --config /root/ql/roi432_inputs/configs/roi432_ee.yaml \
  --dataset /2025233210/lmx/training-data/lerobot/robotwin_clean_place_shoe \
  --episode 0 --frame 20 \
  --processor /2025233210/lmx/checkpoints/Qwen3-VL-4B-Instruct \
  --output /root/ql/roi432_inputs/previews/place_shoe_ep0_f20
```

每个 sidecar 含当前 state、K/E、校准图尺寸、profile hash，不含未来标签或 endpose。
manifest 记录数据来源、完整性、文件 SHA、投影有效率、控制跟踪误差、crop 覆盖情况。
不能只看 `complete=true` 就声称末端定位准确；还应检查多任务、多时刻的可视化和误差分布。
若真实数据的投影明显偏离手部，应停止实验准备、调查状态语义/标定，不能只在在线端换成实测 qpos 导致训练/推理不一致。

## 训练、恢复和评测接口

现有 `tasks/vla/train_lingbotvla.py` 接收 `data.roi_config`（嵌入 profile）和 `data.roi_geometry_root`，不需要新的模型类。
现有训练入口、5k 保存/暂停、DCP 恢复和 350 回合评测工具继续使用；这些新工具不会排队、启动旧控制器或修改共享 claim。
node1 的 `/dev/shm` 限制仍需沿用已验证的**仅作用于本实验子进程**的 loader IPC 环境，改变 ROI 不会自动修复系统 IPC 限制。

首次正式运行前需要真实数据可视化、小步 GPU forward/loss/保存及恢复验证，之后才运行完整10k。此次交付尚未执行这些 GPU 检查。
`xsy_utils/resolution_exp/roi432_runner.py` 是本次单节点运行入口：先单独执行 `--mode smoke`，
完成 2 步保存、DCP 恢复到 4 步并审核后，才能执行 `--mode formal`。
它要求独立 ROI 任务目录、已核验主机、干净且匹配的代码版本、配置 SHA 和预检证据；
保留失败 claim，拒绝已有输出，不会调用旧控制器或重新排队。

2026-10-21 用户再次明确：加速不得改变 global batch、精度或实验对照条件。
因此当前入口固定 micro4×8卡×accum4=global128，保持原精度/优化器/LR/seed/训练数据等配置，
首次运行与所有恢复均显式传入 workers8/prefetch4，防止旧 resume.sh 的 1/1 默认值覆盖配方。
仅使用本实验的私有 loader IPC 配置。其他加速须先证明不改变输入、顺序或训练计算，不能以降低精度、
增大 micro batch、修改梯度累积或关闭训练模块换取速度。
历史全图的约 7.1 秒/步是参考；ROI 的耗时必须排除编译预热，按真实连续步骤的墙钟时间报告。

5k 评测后继续同一 ROI run 时显式指定：

```text
--train.load_checkpoint_path <该ROI运行>/checkpoints/global_step_5000
--train.pause_after_steps 0
```

保持 max_steps=10000 和其余 recipe 不变。ROI DCP 恢复会核验 checkpoint 的预处理 hash；显式恢复失败或 ROI 候选全部失败不能从头继续。
checkpoint 的 HF `config.json` 会保存 ROI config SHA；导出推理 YAML、server 加载时再次检查，以防丢失 ROI 配置后误用全图评测。
评测客户端从 server reset 响应得知 ROI 开关，只在开启时发送当前 head K/E/尺寸和机器人 profile 身份；仍用原始 policy state 计算投影。
